## Home and Discover consolidation

Home and Discover product consolidation was completed as M3.C (17 November 2026), ahead of further integrations.
Independent layouts may show shared sections on both screens; layout visibility never grants network consent.
See `docs/HOME_DISCOVER_CONSOLIDATION.md` for the inherited-feature audit and acceptance criteria,
and `docs/handoffs/M3.C-home-discover.md` for verification and remaining gaps (Artist picks ranking is partial).

## Product principles that survive the platform transition

These come from iOS source, tests and docs (`ios-docs:EverydayExperience.md`, `PlaybackContinuity.md`,
`DesignOverhaul.md`, `ios:DesignSystem/README.md`). They are product rules, not iOS styling.

1. **Opinionated and simple.** Few settings with good defaults; features stay out of the way until they are configured
   (for example, AudioMuse moods appear only when AudioMuse is connected, and Fresh Releases is hidden when empty).
2. **Music- and artwork-first.** Covers lead every surface. The player, album, artist and playlist pages are always dark
   and take their tint from the cover, with contrast caps (luminance ≤ 0.1, white text ≥ 7:1).
3. **Your server, your data, no tracking.** Library traffic goes only to the configured server. Third parties
   (LRCLIB, ListenBrainz, MusicBrainz, Wikidata/Commons, Cover Art Archive) are contacted only for features that need them,
   and they never receive server credentials, custom headers or server identifiers.
4. **Playback reliability over cleverness.** Explicit waiting states (brief waits hidden for 700 ms), late async
   results never override a newer user command, a failed stream only counts as a deleted song on a structured
   not-found, and downloaded copies take over silently when a stream stalls.
5. **Offline is a first-class mode.** Offline shows only what is on the device. Favourites and plays made offline
   queue and sync later. Home keeps its last feed per server. On Android this is the offline-first rule (C1, D9):
   browsing, sorting, filtering and search read only the local Room mirror and never fetch library metadata on
   demand; explicit actions (Instant Mix, stations, lyrics) may call the server, cache the result in Room, and show
   a clear offline fallback when neither the network nor the cache can serve them.
6. **One current-playback surface.** The mini-player is the only "now playing" element outside the full player. There is
   no duplicate "continue listening" card.
7. **The queue is honest.** The queue shows the songs that will actually play next, says where they came from
   ("Playlist · X", "Similar to X"), keeps duplicates distinct, and has one-step undo.
8. **Favourites are hearts**, everywhere except where the OS forces a glyph.
9. **Row tap plays.** Track rows have no "…" button: actions live in long-press menus and swipes. Only the credits text
   opens artists.
10. **Accessible at large text sizes.** Flows are verified at the largest accessibility text size; nothing truncates
    to the point of losing meaning.
11. **Server scope.** Data, pins, recent destinations and shortcuts are tied to one server account and never leak across
    a server switch.

iOS-specific choices **not** to carry over: Liquid Glass, the iOS tab-bar bottom accessory, the search tab role,
SF Symbols and SF Pro, iOS sheets and detents, zoom transitions, `AVRoutePickerView`, the Siri vocabulary, and
background `URLSession` and BGTask semantics.

## Architecture contradictions and recommendations

| # | Contradiction | iOS | Android today | Recommendation |
|---|---|---|---|---|
| C1 | Library data source | Local-first index (`LibraryCatalog`) that falls back to the network until a scan completes; Home "recently added" reads the live server page online | Full Room mirror; no browse metadata is ever fetched on demand (AGENTS.md rule) | **Preserve Android (decided, D9).** Browsing stays local-only: library lists, album and artist pages, sorting, filtering and search read the mirror and never fetch. Explicit actions (Instant Mix, similar songs, stations, lyrics) may call the server; results are cached in Room and work offline next time; with no network and no cache the UI shows a clear fallback ("Lyrics unavailable offline", an Instant Mix built from local genre and artist data). Home and Discover inputs come from the mirror |
| C2 | Queue model | In-memory `[DisplayableSong]` serialised into `PlaybackSession.queueData` | Reference-based SQL queue with a bounded window and Feistel shuffle | **Preserve Android.** Add a "queue source" and an "auto-extended from index" marker to `playback_cursor` and the entries, rather than flattening the queue |
| C3 | Shuffle | Shuffles the upcoming songs only; unshuffle restores the original order | Current track pinned, the rest permuted by seed; unshuffle maps back to flat order. The context is read-only while shuffled | **Preserve Android.** The outcome is the same. Keep "edit while shuffled goes through Up Next" |
| C4 | Up Next | A single mutable list: Play Next inserts after the current song | A context plus a separate up-next block, consumed as played | **Preserve Android.** It is a superset. Present it as one continuous list in the UI (iOS principle 7) |
| C5 | Favourite glyph | Hearts | Stars (Subsonic "star") | **Adapt.** Hearts in the UI; the API stays `star`/`unstar` |
| C6 | ReplayGain default | Off, Track mode, prevent clipping on | Auto mode (album gain in album contexts), on by default | **Preserve Android (decided, D12).** Keep Auto, on by default, with an explicit Off/Track/Album/Auto choice |
| C7 | Theme | System / Light / Dark; artwork pages always dark | System, Light or Dark with maekster tokens; optional Material You; artwork pages always dark (M1.2). Before that: dark-only Material You with the playing artwork tinting every screen | **Adapt.** Add System/Light/Dark with mækster tokens; keep artwork pages always dark; Material You dynamic colour off by default with an optional toggle (decided, D3) |
| C8 | Multiple servers | The service supports many; the iPhone UI exposes only the active server (the Mac has a picker) | A full server list with switching | **Preserve Android (decided, D13).** Keep the multi-server list and switching. The product intends to bring it to iOS later, so treat it as a product feature, not an Android quirk |
| C9 | Credentials | Keychain only; password and headers never in the main store | Plaintext password column in Room `subsonic_sources` | **Replace** with Keystore-backed encryption (M2.1). The password must stay recoverable (Subsonic token auth hashes it with a fresh salt per request), so it is encrypted, not hashed. If the key becomes unusable (device-to-device transfer, which `allowBackup=false` does not block on Android 12+; a Keystore reset; an interrupted first migration), the server is marked "needs sign-in" and the user re-enters the password. The library mirror, downloads, queue and outbox are keyed by server, not password, so nothing else is lost. The migration writes and verifies the ciphertext before clearing the plaintext |
| C10 | Sync scheduling | Index walks only on unmetered networks; background refresh is off (no BGTask) | Foreground-only `AutoSync` timer, Wi-Fi-only by default | **Preserve Android** (it matches the iOS intent) |
| C11 | Swipe app away | iOS keeps playing until the user force-quits | Done in M2.11: `onTaskRemoved` keeps a playing service and stops it only when paused, ended or empty | **Adapt (decided, D8).** Keep playing if playing; stop the service only when paused (the standard Media3 behaviour) |
| C12 | Docs drift | n/a | AGENTS.md says "DOM XML parsing" and mentions `.forgejo/`; the code uses streaming SAX (`SubsonicXml.kt:529`) and there is no `.forgejo/` directory | Correct AGENTS.md in the M0/M1 docs pass |

## Ten largest parity gaps (ranked by user impact × effort)

1. Discover surface and personalised playback (Smart Shuffle, Instant Mix, stations, auto-extend).
2. Credential security and custom headers / reverse-proxy support.
3. Lyrics (server and LRCLIB, synced, cached).
4. mækster identity and app shell (bottom navigation, Library hub, theme, onboarding).
5. Playlist editing and Add to Playlist.
6. ListenBrainz (scrobbling, then recommendations and fresh releases).
7. Extended metadata (format, MBIDs, labels, release types), which unlocks the player format line, discography and integrations.
8. Wrapped (needs play-event history recorded first).
9. Local-folder playback (SAF).
10. AudioMuse-AI integration (moods, Song Path). Lidarr is out of scope (D11).
