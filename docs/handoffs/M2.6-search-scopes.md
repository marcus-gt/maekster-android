# M2.6 Part B: Search scopes and top result

**Status:** complete (12 Nov 2026). M2.6 continues with recent searches per server (Part C).

## Implemented
- The Search filter chips are now single-choice scopes, as on iOS: All, Songs, Albums, Artists, Playlists (saved
  across configuration changes, default All). They replace the old multi-select type toggles; the bar stays where it
  was, above the navigation area.
- All shows a **Top result**: the single best match across types. Then one group per type, in the order of each
  type's best match, five items each with the top result left out, and **See all** (TalkBack: "See all songs") to
  switch to that type's scope. A type scope shows every result of that type (still up to the 50-row query limit) and
  no top result. A new scope starts scrolled to the top.
- Cross-type ranking is a Kotlin port of iOS `LibrarySearchRanking.score` (`SearchRanking.kt`): exact 1000, prefix
  800, contains 600, every query word prefixes a title word 500, every word in title plus detail 200. Text is folded
  for case and diacritics and punctuation runs become spaces, so "joga bjork" scores "Jóga" by Björk and "ac dc"
  equals "AC/DC". Ties: title, then key. Within a type, higher scores move up and equal scores keep the database
  order (Part A's rank and the sort-name mode). Duplicate rows are dropped by key.
- Replaced the old fixed group order (playlists, artists, albums, songs) and its tests.
- No schema, dependency or network change. New strings: All, Top result, See all, See all %1$s.
