# M2.10 emulator check, plus a download crash fix

**Status:** DONE. M2.10 is complete. Based on 49baa2e0.

## Crash found and fixed

- Downloading an album crashed the app, and it crashed again on every relaunch while rows were pending:
  `SQLException: Error code: 8, attempt to write a readonly database` in
  `LibraryDao.recomputeDownloadedArtistArt` ← `DownloadRepository.refreshDownloadedArtistArt` ←
  `apply`/`reconcileRows`.
- Cause: Room generates `@RawQuery` as read-only (`performSuspending(db, isReadOnly = true, …)`).
  Outside a transaction, the UPDATE ran on a pooled reader connection, which is read-only. This is a
  regression from b2a1716b (3 Nov), which moved the query to `@RawQuery`. `recomputeArtistArt` and
  `recomputeArtistAggregates` are safe because they only run inside `recomputeAggregates`'s `@Transaction`.
- Fix: `@Transaction` on the `recomputeDownloadedArtistArt(sourceId, artistIds)` wrapper.
- Test: `LibraryDaoTest.downloadedArtistArtWritesThroughPooledConnections` uses the new
  `createFileTestDatabase()` (file-backed, pooled like the app). An in-memory database has one
  connection and cannot catch this. The test failed with the same SQLITE_READONLY error before the fix
  and passes after it.
- Rule for later work: any `@RawQuery` that writes must be called inside a transaction.
- Checks: ktlintFormat, assembleDebug, ktlintCheck and lintDebug pass. The full suite ran 1586 tests;
  3 failed, all known HomeScreenshotTest 5 s load timeouts (homeOffline, homeRecentlyPlayedArtistsList,
  homeRecentlyAddedList). The class passes when run on its own (5/5).

## Emulator results (API 37 emulator, Navidrome, debug nightly build)

- Storage: "Cached covers" shows the size. "Clear artwork cache" asks for confirmation and then shows 0 B.
  "Library on this device" reads 944 artists · 1,760 albums · 18,600 songs · 9 playlists. "Database size"
  reads 39.41 MB. "Sync library now" switches to "Syncing…", can't be tapped while syncing, then comes
  back. Sync is read-only.
- Transfers (24-song FLAC album): each row shows "Downloading", a progress bar, "24.72 MB of 52.03 MB"
  and a Cancel button. Cancel removed one song (log "removed 1 download(s)"; 23 songs, 867 MB remained).
  The section disappears when the batch finishes, leaving the artist and album group.
- Offline Home: with Offline mode on, Home leads with "Offline mode" and "23 songs available offline",
  followed by Downloaded albums, artists and songs. "Turn off offline mode" returns to the online Home.
- Cleanup: "Delete all" (confirmed, "Deleting will free 867 MB") left "No downloads yet.". Offline
  mode is off. No crashes after the fix (crash buffer checked).
- No server writes: downloads and sync only read from the server.
