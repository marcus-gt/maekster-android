# M2.10 Part A: download collection ownership

**Status:** DONE (JVM-tested; no device check: no UI change). Based on 768e8373.

## Audit finding

Android had no collection ownership. `deleteAll` / `cancelAll` / `removeList` for an album, playlist
or artist removed every download row in that list, so deleting an album's downloads also took songs a
downloaded playlist relied on (and vice versa). iOS keeps owners per download (track / album /
playlist) and `OfflineLibraryRemovalPlanner` purges a collection's songs minus those another
downloaded collection holds; removing a single track always purges it.

## Implementation

- Schema 53 (`MIGRATION_52_53`, `53.json`): `download_collections (sourceId → sources cascade, kind,
  refId)`, PK all three. `kind` is a `DownloadList` name (Album, Playlist, Artist).
- The migration backfills lists that are already fully downloaded: every song has a download row
  of any status, with at least one song. Albums and playlists only; artists and partial lists are not
  guessed (they behave as before until downloaded again as a whole).
- `DownloadDao`: `recordCollection`, `forgetCollection`, `collections(sourceId)`.
- `DownloadRepository.downloadAll` records the collection under the download mutex. `cancelAll`,
  `deleteAll` and `removeList` go through `releaseList`: forget this collection, compute the song IDs
  of every remaining recorded collection (existing `songIds` per list), then remove only selected
  rows outside that set. Single-song `remove` and `cancel(songIds)` still purge unconditionally (iOS
  track removal). Playlist deletion (`deleteAll` via the delete dialog) gets the same protection.
- Memory: retained IDs are the songs of recorded collections, which is bounded by what is downloaded.
  This path already loads all download rows.

## Verification

- `DownloadRepositoryTest` (+4, 67 total): album removal keeps a downloaded playlist's song;
  playlist removal keeps the album's songs, and the album removal then takes all; cancelling an album
  keeps a queued transfer a playlist needs; single-song removal deletes even a playlist-held song.
- `MigrationsTest` (+1, 19): backfill records only the fully downloaded album and playlist (not the
  partial album or partial/empty playlists); the chain matches schema 53.
- Mutation: an empty retained set fails the 3 ownership tests; restored.
- ktlintFormat, assembleDebug, ktlintCheck and lintDebug pass. Full suite 1578 tests: only the three
  known HomeScreenshotTest timeouts, which pass 5/5 in isolation.
