## iOS reference (ListenBrainzSettingsView)

A scrobbling toggle, plus a footer warning against duplicates when the server already relays to
ListenBrainz. When signed out, a token field (secure), a server URL and Validate, with the error
shown inline and a hint on where to find the token. When connected, "Connected as", Active or Paused,
Replace token, and a confirmed "Forget credentials". The separate recommendations username belongs to
M3.3 and is not built here.

## Implementation

- **Playback page:** a "ListenBrainz" row after "Scrobble to server". `listenBrainzSummary` shows Off,
  "On · user", "Paused · user" or "Enter your token again", with "· N waiting" when listens are queued.
  `SettingsScreen` takes `listenBrainz: ListenBrainzState` (default signed out, so screen tests need no
  Koin). `SettingsRoute` reads it from `ListenBrainzSettingsViewModel`.
- **`ui/settings/ListenBrainzDialog.kt`:**
  - `ListenBrainzSettingsViewModel` maps the repository state. `connect` maps `ConnectResult` to
    `ListenBrainzConnectError`: InvalidToken; Network for transient non-HTTP errors; otherwise Server.
    It also has `setEnabled` and `disconnect`.
  - `ListenBrainzSettingsRoute` connects the ViewModel to the dialog. `ListenBrainzDialog` is stateless.
  - Signed out, or with an unreadable token: the explanation, a masked token field (password keyboard),
    a server field (Uri keyboard, prefilled), the token hint, the error, the duplicate warning, and
    Connect (disabled while blank or busy, "Connecting…") / Cancel.
  - Connected: "Connected as …", a "Send listens" switch, the pending count, the duplicate warning, and
    Disconnect with confirmation ("maekster forgets your token and any listens still waiting").
- Strings say "maekster" in lowercase. Koin registers `viewModel { ListenBrainzSettingsViewModel(get()) }`.

## Gotcha found

Under Robolectric, a text field inside a dialog with `@Config(qualifiers = RobolectricDeviceQualifiers.PixelXL)`
never lets Compose go idle (`AppNotIdleException` after 60 s, or a hang in `setContent`). The dialog
test therefore runs without the qualifier, like `RenamePlaylistDialogTest`. Neither the keyboard type,
the masking nor the scroll was the cause (each was ruled out by test).
