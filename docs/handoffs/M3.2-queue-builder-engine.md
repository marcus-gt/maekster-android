# M3.2 Part E1: Queue Builder engine (local)

**Status: DONE (engine only; no UI yet).** Based on 60e1d312; tree initially clean.

## Part E plan

iOS Queue Builder (`QueueBuilderService`, `QueueBuilderIndex`, `QueueBuilderViewModel`, `QueueBuilderView`) is
large, so Part E is split:
- **E1 (this):** local engine: genre and decade index, match count, bounded random build. Room only.
- **E2:** Discover card plus picker sheet (genres, decades, length 15–120, default 50; persisted picks;
  summary line). Plays as a new endless `QueueCollection.QueueBuilder`; empty result shows a message.
- **E3:** refill a Queue Builder queue with its own picks (iOS `playBuiltQueue` refill closure) rather than
  "Similar to …" autoplay.
- **E4:** main-genre columns from a Discogs-style taxonomy. iOS ships `Resources/DiscogsGenres.json`;
  review its licence before copying (FEATURE_PARITY flags it).
- Moods wait for AudioMuse (not on Android yet). iOS's server fallback while its index is incomplete isn't
  needed: the Android mirror is always complete after sync.

## Implementation

- `data/mix/QueueBuilder.kt`: `QueueBuilderSelection(genres: keys, decades: first years)`, `QueueBuilderGenre`,
  `QueueBuilderIndex(genres, decades)`, and `QueueBuilder(MixDao)` with `index`, `matchCount` and `build`.
- Matching follows iOS: any picked genre AND any picked decade. Nothing picked in a group matches everything
  in it. Once a decade is picked, songs without a year drop out. Each song appears at most once.
- Genres are keyed by `trim().lowercase()` (Unicode-aware, locale-invariant), so case and space variants
  merge. The most used spelling names the genre (ties alphabetical). Sorted by song count, then name.
- Picked keys are resolved to stored spellings, so `g.genre IN (...)` uses `song_genres(sourceId, genre)`.
- Decade uses the album's `year` (Android has no per-song or original release year). iOS prefers the original
  year, so reissues may land in a later decade here.
- `MixDao`: `genreSpellings`, `decadeCounts`, `builderMatchCount`, `builderSongs` (`ORDER BY RANDOM() LIMIT`).
  All are aggregated or bounded. `downloadedOnly` restricts everything to completed downloads.
- `build` takes 1..200 songs (iOS UI 15–120) and excludes at most 2,000 ids, keeping SQL bind counts bounded.
- Koin: `single { QueueBuilder(mixDao) }`, unused until E2.
- No schema, dependency or toolchain changes.

## Known limits

- A genre's index count sums per spelling, so a song tagged with two spellings of one genre counts twice
  in the index only. The match count is exact.
- Songs on albums with no year never match a decade.
