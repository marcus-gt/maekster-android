# M3.5 E2: Song Path card and picker

**Status: DONE.** Clean start at aa41049e on main. Git started 47
commits ahead and one behind origin/main. E1 supplied the finite queue; E2 connects it to Discover.

## Implemented

- Discover has a reorderable Song Path shelf. The card is shown when online and AudioMuse is usable
  for the active server. It supports From/To rows, Swap, a 5–50 target (default 25), Play, progress
  and snackbar feedback. From follows the current song on the same server until explicitly edited
  or swapped. Draft choices are scoped to the server and the Discover composition.
- The bottom sheet offers local suggestions (Now Playing, recent, top by mirrored play count,
  favorites and Surprise Me) and bounded, debounced mirror search. The opposite song is excluded.
  The five AudioMuse moods are available when the opposite endpoint is a song or empty.
- The existing finite queue handles playback. A source mismatch or newer playback command prevents
  a delayed result from replacing the queue. A local library query is enough for the picker, so
  AudioMuse receives endpoint values and length only when Play is tapped.
- Key files: `ui/discover/SongPathCard.kt`, `DiscoverViewModel.kt`, `DiscoverScreen.kt`,
  `data/db/LibraryDao.kt`, `playback/SongPathPlayer.kt`, `PlaybackController.kt`.
  Updated the roadmap, parity matrix and privacy disclosure.
