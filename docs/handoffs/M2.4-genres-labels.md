# M2.4 Part C: Genres and Labels

**Status:** complete (12 Nov 2026). Stop here; Part D is not started.

## What was built

- Library hub entries for Genres and Labels open paged lists with artwork and distinct album counts.
- Name and Most albums sorts, direction reversal, in-list substring search and Downloaded filter.
- A collection opens its albums, newest year first, unknown years last, then name and ID.
- All browsing reads the Room mirror. No schema, dependency, sync or playback architecture changes.

## Key files

- `data/db/AlbumCollectionQuery.kt`: grouping, album membership and offline availability queries.
- `data/model/AlbumCollection.kt`: collection kind and summary.
- `LibraryDao`, `LibraryRepository`: paging and download availability.
- `LibraryViewModel`, `LibraryScreen`, `AlbumCollectionsContent`, `LibraryHubViewModel`: lists and options.
- `AppRoot`, `HomeListViewModel`, `HomeListScreen`: URI-encoded collection routes and album lists.
- `UserPreferences`: separate genre/label list preferences; strings in English resources.

## Decisions

- Genres use every song_genres tag, including secondary tags, rather than the album's single genre.
- Labels use every album_labels row. Blank names are excluded.
- Grouping and membership use SQLite NOCASE, with COUNT(DISTINCT album ID).
- Offline genres require a completed download of a song carrying that genre. Offline labels require any
  completed song download on the album. Counts and offline hub availability use the same rules.
- Existing album detail, context menus and playback stay in place.
