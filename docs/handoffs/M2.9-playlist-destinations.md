# M2.9 Part C: recent playlist destinations

**Status:** COMPLETE. Based on c5b1a4bc; committed with this handoff.

## Implementation

- Room schema 50 (`MIGRATION_49_50`, exported `50.json`): `playlist_destinations` (sourceId, playlistId,
  usedAt), primary key (sourceId, playlistId), index (sourceId, usedAt), cascade on server delete (D6).
- `PlaylistDestinationDao.record` moves a playlist to the top and keeps the newest five per server
  (iOS keeps five); `usedAt` is forced past the server's newest so ties and clock steps cannot reorder.
  `recent(sourceId)` resolves through the mirror: a playlist no longer mirrored is hidden but kept, and
  reappears when synced again.
- `PlaylistRepository` records a destination only after a successful add (or an empty create), and
  exposes `recentDestinations(sourceId)`.
