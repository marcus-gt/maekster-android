# M3.2 Part E2: Queue Builder card and picker on Discover

**Status: DONE.** Based on 4328452f (E1 engine); tree initially clean.

## Implementation

- `QueueCollection.QueueBuilder` (endless, "Queue Builder"): the header reads "Playing from Queue Builder"
  and autoplay never relabels it "Similar to …".
- `QueueBuilderPicks(selection, length)` (15–120 in steps of 5, default 50, `clampLength`) and
  `QueueBuilderIndex.available(selection)`, which keeps only picks the current index still offers.
- `UserPreferences.queueBuilderPicks(sourceId)` / `setQueueBuilderPicks`: genre keys and decades as string sets
  plus length, keyed per server (`queue_builder_*_<sourceId>`) as on iOS.
- `QueueBuilderPlayer` (like `SmartShufflePlayer`): builds on the active server (downloads only offline,
  `mixDownloadedOnly`), then `playMix(..., QueueCollection.QueueBuilder)`.
- `QueueBuilderViewModel`: loads the index per server and offline state (`refresh()` on Discover entry and on
  opening the picker), keeps saved picks in memory per server, and saves every edit. It shows and builds only
  the available part, so a genre hidden offline comes back online. It counts matches, and `build` shows
  `queue_builder_no_match` on an empty result or `mix_failed` on an error.
- UI (`QueueBuilderUi.kt`):
  - **Card:** after Smart Shuffle. Summary (genres in index order, decades newest first, else "Anything in your
    library"), an offline note, Play (disabled at 0 matches) and Edit picks.
  - **Picker:** full-height `ModalBottomSheet`. Reset, a genre filter (picked genres stay visible), genre and
    decade `FilterChip`s with counts, Clear per section, the length slider, and a footer with the match count
    and a full-width Build. The stateless `QueueBuilderContent` is used by tests.
- Koin: `QueueBuilderPlayer` single, `QueueBuilderViewModel`. No schema or dependency changes.
