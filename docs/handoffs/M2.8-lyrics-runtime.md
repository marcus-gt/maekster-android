# M2.8 Part J: lyrics runtime wiring

**Status:** COMPLETE. Based on bf35796a; committed with this handoff.

## Implementation

- `LyricsLoader` (data/lyrics) turns the playing song, lyric preferences, offline state and a retry
  counter into `LyricsState` (Idle, Loading, Found, Missing(offline), Failed). It reloads only when
  song identity/metadata, source, LRCLIB permission, connectivity or retry change; star changes,
  timing correction and the preview toggle reload nothing. A newer request cancels the older one
  (`transformLatest`). Loading is emitted only when the song changes, so a connectivity reload keeps
  lyrics on screen.
- `LyricsState.Found.display(language, correction)` picks the variant (`LyricsSelection`) and builds
  `LyricsTiming` with the listener correction.
- `LyricsViewModel` (ui/playback) exposes `LyricsUi(state, display, showCurrentLine)`, plus `retry`,
  `selectLanguage` (session-only) and `setPaneOpen`. As on iOS, nothing is looked up unless the pane
  is open or the current-line preview is on.
- `playingSong(state, song)` maps `PlaybackController.state` to the mirrored Room `Song`.
- `SourceRepository.serverLyrics(song)` builds a `SubsonicLyricsProvider` for the song's server
  (refuses offline/needs-sign-in, like `artistBiography`).
- Koin: singletons `LyricsCache`, `LrclibProvider` (its own OkHttp client, no shared interceptors or
  server headers), `LyricsRepository`; `LyricsViewModel` with offline = offline mode OR no network.

## Known limits

- Server lyrics for a song from a non-active server go out without that server's custom headers
  (shared client scopes headers to the active server); same as `artistBiography`.
- Language choice is per ViewModel, not persisted.
