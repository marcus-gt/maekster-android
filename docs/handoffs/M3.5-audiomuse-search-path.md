# M3.5 A2: AudioMuse search and Song Path transport

**Status: DONE (unwired transport).** Clean start at fb25207a.

## Implemented

- AudioMuseClient now exposes warmup, search and findPath alongside moodScores.
- Lazy serialized server discovery: default_id, otherwise first server_id/name. Discovery failure
  is cached as unscoped for this client, matching iOS; cancellation propagates and permits retry.
- CLAP search POST sends query, bounded limit (1–500) and resolved server. Keeps fp_ IDs,
  title/author/album/similarity; local resolution belongs to a later subtask.
- Warmup POST is best effort (false on transport/HTTP/decoding failure), cancellation still propagates.
- Song Path GET encodes song/mood endpoints, server, max_steps (2–500) and path_fix_size=true.
  Only one mood endpoint allowed; preserves path order and duplicates. No queue/playback changes.
- Strict track decoding and maximum 500 results; no result list means failure, not empty success.
- Shared isolated authenticated/cancellable transport retains proxy paths and rejects redirects.
  Empty response is allowed only for warmup. No settings, DI, cache, UI or new dependencies.
- iOS client semantics were read in the preceding session; no reference source copied.
