# M2.9 Part F: rename a playlist from its page

**Status:** COMPLETE. Based on d4d4d24b; committed with this handoff.

Scope (iOS PlaylistRenameAlert/PlaylistRenamer): "Rename…" in the playlist page's menu for the
user's own playlists outside offline mode; dialog prefilled with the current name; Rename disabled
while the trimmed name is empty or unchanged; the trimmed name is sent. Android keeps the dialog
and draft on failure (M2.9 rule) and shows "Renamed to <name>" on success. iOS's Mood/Wrapped
exclusion and gradient-cover rebake have no Android counterpart yet; pins resolve names from the
mirror, which `PlaylistRepository.rename` refreshes. Delete is a separate later part.

## Implementation

- `ui/playlist/RenamePlaylistViewModel` (+ `RenamePlaylistRequest`, `RenamePlaylistUi.canRename`),
  Koin `viewModel { params -> … }`; `RenamePlaylistDialog`/`RenamePlaylistRoute` (Material
  AlertDialog, all text selected, IME Done submits). The dialog can't be dismissed while busy:

  only when `canEdit`. `canRemoveSongs`/`canRemove` renamed `canEditPlaylist`/`canEdit` (one rule).
