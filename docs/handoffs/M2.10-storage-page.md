# M2.10 Part C: Storage page (artwork cache, library counts, sync now)

**Status:** DONE; emulator-verified on 14 Nov 2026 (see `M2.10-emulator-check.md`). Based on 0520f891.

## iOS (SettingsPages Storage + LibraryIndexStorageSection)

Storage has Downloads (clear all), Stream cache (size stepper, cellular, clear), Artwork (disk usage,
cache-artwork toggle, clear with confirmation) and Library index (disk usage, counts of artists /
albums / songs / playlists / recommendations, Synchronize index, Index full server, Delete index).

## Implementation (Android interpretation)

- Settings > Storage now has, after Downloads, an **Artwork** section: "Cached covers" (Coil disk
  cache size) and "Clear artwork cache" with a confirmation. That clears Coil's disk and memory
  caches only; covers stored with downloads (`ArtworkStore`) are kept, as the dialog says.
- The existing **Library sync** section now starts with "Library on this device" ("941 artists ·
  1,757 albums · 18,578 songs · 9 playlists" for the active server), "Database size" (db + WAL file)
  and "Sync library now" (`SyncManager.requestSync`), which reads "Syncing…" and is disabled while a
  sync runs. The existing sync mode/interval/concurrency rows follow.
- `LibraryDao.libraryCounts(sourceId)` / `LibraryRepository.libraryCounts`, `LibraryCounts`.
- `StorageSections.kt`: `ArtworkCache` interface + `CoilArtworkCache`, `StorageViewModel`
  (counts flow, sync status, request lambda, cache, database files; sizes recomputed on IO when
  counts/status change or after clearing), stateless `ArtworkStorageSection` and `LibraryStorageRows`.
  `SettingsScreen` gets `storage`/`onClearArtwork`/`onSyncNow` with defaults (tests unchanged), and
  `SettingsRoute` wires `StorageViewModel` (Koin).
- `ValueRow`, `ActionRow` and `SectionHeader` in SettingsScreen.kt are now `internal` for reuse.
- Not mirrored: a stream-cache clear or size (Android's stream cache is a 64 MB scratch buffer, D7;
  a persistent replay cache is issue #2), the cache-artwork toggle, recommendations, and
  index-full-server/delete-index (Android's library mirror is the app's data, not an optional index).
