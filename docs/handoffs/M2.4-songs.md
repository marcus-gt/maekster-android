# M2.4 part B: Library Songs list

**Status:** complete. Committed together with this handoff (see Git).

## What was built

- **Songs entry:** the Library landing list has a Songs entry after Artists. The list has the same top bar, search and
  options sheet as the other lists.
- **Sorts:** Title, Artist, Album and Added (newest first by default), each reversible.
- **Filters:** favorites (any / only / none), downloaded, and in-list search (FTS from 3 characters, a substring match
  below that).
- **Offline:** the list shows only downloaded songs, and the hub offers Songs only when something is downloaded.
- **Rows:** cover, download state, a favorite heart and the duration.
- **Playback:** a tap plays the list as shown, from that row. A shuffle button shuffles the same list.

## Key files

- `data/db/SongListQuery.kt` (new): `SongListSpec` (sort, direction, favorites filter, downloaded, search, sort-name
  mode) with a versioned `encode`/`decode`, plus the shared SQL (`songsPageQuery`, `songsCountQuery`, `songOrder`).
- `LibraryDao` (`songsPaging`, `downloadedSongsPaging`, `hasDownloadedSongs`) and `QueueDao` (`libraryLength`,
  `librarySongs` over `@RawQuery`).
- `QueueRepository` / `PlaybackController`: the `QueueKind.Library` resolver, `libraryEntry`, and
  `playLibrarySongs` / `shuffleLibrarySongs`.
- UI: `LibraryViewModel` (`songListSpec`, `songs`, `playSongs`, `shuffleSongs`), `LibraryScreen` (`LibraryTab.Songs`,
  sort options, shuffle button) and `LibrarySongsContent.kt` (new).
- Schema 42 (`MIGRATION_41_42`) adds `index_songs_sortName`, `index_songs_artistSort` and `index_songs_created`.
  The schema is exported to `app/schemas/.../42.json`.
- `UserPreferences`: `SongSort` and `LibraryListTab.Songs`, stored under the key `library_songs`.

## Decisions

- **Queue reference:** the queue stores the encoded spec as `refId`, and the resolver runs the same SQL as the paged
  list. The order is identical, and no song IDs are copied into the queue. A reference that doesn't decode plays
  nothing.
- **Start position:** taken from the tapped row's index. The pager enables placeholders so that index stays absolute.
  There is no `rank()` for this kind, so re-anchoring after edits uses the generic offset path.
- **Preference key:** `library_songs`, not `songs`. An old upstream Subtracks Songs tab stored a sort and filter under
  `list_query_songs`; on the emulator the list opened pre-filtered to favorites until the key changed.
- **Shuffle mode:** a new play keeps the current shuffle mode, as albums and playlists already do.

## Tests and checks

- **Unit tests (Robolectric):**
  - `QueueRepositoryTest`: queue order equals list order for 9 sort, filter and search cases; a spec that doesn't
    decode plays nothing.
  - `SongListQueryTest`: encode/decode round trip, including a search containing `|`; order terms.
  - `LibrarySongsListTest`: a tap passes the row index; shuffle is hidden when the list is empty.
  - `UserPreferencesTest`: the old `songs` key is ignored.
  - `LibraryHubScreenTest` (updated), `MigrationsTest`: schema chain and NOCASE collation on the new indices.
- **Full suite:** ktlint, lint and assemble pass (final result in the commit report).
- **Emulator (Pixel 9 AVD, real Navidrome library, about 18.5k songs):**
  - Pass: schema 41 → 42 migrated with no crash, and the default Title sort with no filters.
  - Pass: tapping row 3 plays it, and Next plays row 4.
  - Pass: searching "VTSS" gives 5 rows; playing the third, Next stays in the results and the queue ends after the
    last one.
  - Pass: shuffle stays inside the search results.
  - Pass: the heart toggles on and off, and the list keeps its scroll position.
  - Pass: Added sort with the favorites-only filter: Nairobi → Next → toucan, matching the list.
  - Pass: the Downloaded filter with no downloads shows the filtered empty state.
  - Pass: Now Playing shows "Now playing: songs".

## Open issues and untested behaviour

- **Not tested:**
  - Offline with real downloads (the emulator has none).
  - The 200k-song `queryTiming` measurement.
  - The integration servers (gonic, LMS, Nextcloud Music).
- **Possible slow toggle:** toggling shuffle off on a Library queue took a visible moment on the emulator. This is
  unmeasured. The offset fallback for a list of tens of thousands of songs may be slow and is worth profiling.
- **Leading spaces:** some server titles start with a space (" 8000"), so they sort first under Title. This comes from
  existing sort-name handling, not Part B.
- **List lag:** after a filter change the list briefly shows the previous rows before refreshing. This is shared
  list behaviour.
