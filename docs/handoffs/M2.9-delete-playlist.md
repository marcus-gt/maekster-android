# M2.9 Part G: delete a playlist from its page

**Status:** COMPLETE in code and JVM tests; a REAL delete has NOT been run on a device (needs the
user to authorize which playlist may be deleted). Based on 933d0738; committed with this handoff.

Scope (iOS DeletePlaylistConfirmation + PlaylistService.deletePlaylist): "Delete playlist" (error
tint) in the playlist page menu, edit rule as remove/rename. Confirmation "Delete “name”?"; with
downloads "Delete playlist only" / "Delete playlist & downloads" / Cancel stacked, otherwise the
standard Cancel, Delete row. Downloads are purged only after the server delete succeeds and before
the mirror rows go (`DownloadRepository.deleteAll` resolves songs through them). Success: snackbar
"Deleted <name>", the page closes. Failure: the dialog stays with the error and can be retried.

## Implementation

- `PlaylistRepository.delete(…, afterServerDelete)`: writer delete (idempotent), then the hook,
  then `removePlaylist` in `finally` so a failing hook still clears the mirror.
- `ui/playlist/DeletePlaylistViewModel` (+ `DeletePlaylistRequest(hasDownloads)`, `DeletePlaylistUi`),
  Koin wires `purgeDownloads` = `deleteAll(Playlist)` + `PlaybackController.refreshMediaItems()`.
- `DeletePlaylistDialog`/`DeletePlaylistRoute` (per-opening `PlaylistSheetScope`, not dismissable
  while busy). `ItemActions.deletePlaylist`; PlaylistDetailRoute sets it when `canEdit`,
  `hasDownloads = downloadStatus.downloaded > 0`, and calls `onBack()` once deleted.

## Known issues (follow-ups)

- Queue caches (`QueueRepository.invalidateLibraryCache`) are not invalidated after playlist edits or
