# M2.4 Part G: playlist summary footer

**Status:** complete (12 Nov 2026). Implemented and verified by Claude Code; committed on its own (see Git).
With this part, every item in the M2.4 roadmap row is done.

## What was built

- Under the last track of a playlist: "11 songs · 1 hr", counting the songs the list actually shows. Offline that
  means the downloaded ones; a song missing from the mirror is not counted; duplicates count twice.
- The header follows the iOS hierarchy: the owner and "Updated <relative date>" (`DateUtils`, so "2 days ago", then a
  date after a week). The count and length moved from the header to the footer. Before, the header used the server's
  playlist totals, which were wrong offline.
- No footer until the totals are counted (no "0 songs" flash) or when the list is empty.

## Key files and decisions

- `LibraryDao.playlistTotals(sourceId, playlistId, downloadedOnly)`: `COUNT(*)` and `SUM(duration)` over the same join
  as `playlistSongs`, with the same `DOWNLOADED_SONG` filter offline. The list stays paged; nothing is loaded to sum it.
- `ListTotals` (in `Models.kt`), `LibraryRepository.playlistTotals`, `PlaylistDetailViewModel.totals` (null until counted).
- `PlaylistDetailScreen`: `PlaylistSummary` footer item (caption style, `playlistSummary` test tag) and the new subtitle.
  The `offline` parameter is gone (the totals carry it). New string `playlist_updated`.
- Durations use the existing short format ("1 hr 5 min", via `totalDurationText`) rather than iOS's long units, to
  match the album page.

## Verification

- `PlaylistTotalsDaoTest`: count and length online, with a duplicate entry, an unknown duration and a missing song;
  offline counts only completed downloads; another playlist and an unknown playlist stay separate.
- `PlaylistDetailScreenTest`: the footer shows the counted totals, not the server's, and the header shows the owner and
  "Updated 2 days ago". There is no footer before the totals arrive.
- No separate mutation run. Both tests exercise new code that did not exist before.
- Final: ktlintFormat, assembleDebug, testDebugUnitTest (1,207 tests, 0 failures), ktlintCheck, lintDebug.
- Pixel 9 API 37 with the real Navidrome mirror: an 11-song playlist shows the owner and "Updated Nov 1, 2026" in the
  header, and "11 songs · 1 hr" under the last track. The rows add up to 60 min 47 s.

## Not verified / limits

- Offline with real downloads (DAO test only), API 35, TalkBack, 2× font, and a very large playlist's timing.
- iOS's featured-artists shelf under the footer is not part of this subtask (FEATURE_PARITY lists it separately).
