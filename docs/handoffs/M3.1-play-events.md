# M3.1 Part A: local play events

**Status:** DONE. Based on b62517a6 (Milestone 2 close-out, PR #12).

## Plan for M3.1 (ListenBrainz scrobbling and play events)

- **A (this):** a `play_events` table, recorded when a play reaches the scrobble threshold.
- **B:** a ListenBrainz client (validate-token, submit-listens `playing_now`/`single`/`import`) behind an
  interface with a fake; OkHttp and `org.json`; iOS's error mapping, where only network, 429 and 5xx
  are transient.
- **C:** the account (token through `CredentialStore`, root URL with default `https://api.listenbrainz.org`,
  enabled flag) and the `pending_listens` offline queue. A `ListenSink` is fed by `Scrobbler`.
  `playing_now` on start; `single` at the threshold. A transient failure queues the listen and a
  permanent one drops it. Success flushes the queue as `import`.
- **D:** Settings UI: token entry with validation, the username, enable, the pending count, Disconnect.

## iOS reference

- iOS has no local play table; Wrapped reads the ListenBrainz history (`ListenHistoryStore`). The
  roadmap adds `play_events` so Android has its own history, even without ListenBrainz.

## Implementation

- `data/model/PlayEvent.kt`: `PlayEvent` (`play_events`, schema 55). It holds an autoincrement id,
  `sourceId` (FK, cascade), `songId`, `playedAt` (epoch seconds), and title/artist/album/`durationMs`
  snapshots. Indices are (sourceId, playedAt) and (playedAt). There is no FK to songs, so a play
  outlives a pruned song.
- `LibraryDao.recordPlay` (already called once per `Scrobble.Submission`, i.e. a real threshold
  play) now first runs `insertPlayEvent`, an INSERT … SELECT from `songs`. An unknown song records
  nothing.
- `PlayEventDao`: `between(sourceId, from, to)` and `count(sourceId)`. `MIGRATION_54_55` uses Room's
  exported SQL.
