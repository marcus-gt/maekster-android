# M2.5 Part E: Per-server pin persistence

**Status:** complete (12 Nov 2026). M2.5 pins UI remains unfinished.

## Scope and implementation
- Room schema 43 adds pins, keyed by sourceId/kind/refId with an index on sourceId/position.
- PinKind: Album, Playlist, Artist; references only, matching the roadmap's data model.
- PinDao provides bounded ordered Flow reads, observable isPinned, pin and unpin.
- Pin uses one atomic INSERT OR IGNORE ... SELECT MAX(position)+1; duplicates do not reorder.
  Unpin leaves position gaps; re-pin appends after the remaining items, independently per server.
- Source FK cascades on deletion. Pins do not FK to mirrored entities, so sync pruning does not
  delete the user's pins. UI resolution of a missing reference belongs to the next subtask.
- Hand-written MIGRATION_42_43 and exported 43.json. No dependency, build config or UI change.
- iOS PinService/PinnedItem inspected for duplicate and ordering semantics; no source copied.
  Android scopes identity/order to server and uses the existing offline mirror instead of metadata snapshots.
