# M3.5 B1: per-server AudioMuse configuration storage

**Status: DONE (storage only; unwired).** Clean start at 4bca709e.

## Implemented

- B split into B1 storage/repository and B2 Settings UI/runtime wiring.
- Schema 61: audiomuse_config holds one URL and optional token ciphertext per source; source FK
  cascades on delete. Handwritten 60→61 migration; exported schema generated by Room.
- AudioMuseConfiguration validates HTTP(S) URLs, defaults missing scheme to HTTPS, retains proxy
  paths and rejects URL credentials/query/fragment. HTTP remains allowed for self-hosted instances.
- save replaces URL/token atomically. Blank token means no authentication; tokens are sealed through
  CredentialStore and decrypted/compared before saving. Failure leaves existing config untouched.
- observe exposes only URL, hasToken and tokenUnreadable; connection returns null if decryption fails.
  AudioMuseConnection and stored entity avoid generated toString methods exposing secrets.
- disconnect removes only the specified source's AudioMuse config. No global active-source assumption.
- These are server connection credentials, kept alongside existing source/header configuration in Room;
  UI/playback preferences remain in DataStore.
- No DI, Settings UI or network use yet. No dependencies or playback changes.
