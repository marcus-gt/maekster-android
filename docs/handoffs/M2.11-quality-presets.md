# M2.11 Part B: stream quality presets plus Custom

**Status:** DONE. Based on 0c7ef295 (Part A: `M2.11-swipe-away.md`).

## iOS (StreamQuality)

There are three choices per network: Original (no format or bitrate), MP3 320 kbps and MP3 192 kbps.
Defaults are Original on Wi-Fi and MP3 192 on cellular. Android already stores any max bitrate and
format; FEATURE_PARITY says to offer the iOS presets first and keep that range behind "Custom".

## Implementation

- `ui/settings/QualityPreset.kt`: the `QualityPreset` enum (Original, Mp3High = 320/mp3,
  Mp3Standard = 192/mp3) maps each preset to a `StreamQuality`. `QualityPreset.of(quality)` returns
  null for a custom value and treats an empty format as none. Storage is unchanged: same keys, same
  encoding, no migration.
- `QualityDialog`, shared by Wi-Fi, Mobile and Download quality, now leads with a "Quality" group:
  the three presets plus Custom. Choosing a preset sets its bitrate and format. Custom reveals the
  existing bitrate and format groups and keeps the current values. A stored custom value opens on Custom.
- `qualityLabel`: rows show the preset name ("Original", "MP3 192 kbps") and otherwise the existing
  "format · bitrate" summary.
- New strings: `quality_title`, `quality_original`, `quality_mp3_320`, `quality_mp3_192`, `quality_custom`.

## Verification

- `SettingsScreenTest` (+5, 15): preset names in the rows, the custom summary ("opus · 256kbps"),
  choosing MP3 320 saves 320/mp3 with no bitrate list shown, Custom reveals the lists and saves
  256/opus, and a custom value opens on Custom.
- Mutations: without the preset label, the row test fails; always opening on Custom fails the
  preset test. Both restored.
- Emulator (API 37): Playback shows "Original" (Wi-Fi) and "MP3 192 kbps" (Mobile). The Mobile dialog
  lists the presets with MP3 192 selected; Custom reveals the bitrates with 192 kept. Cancel left the
  setting unchanged. No crashes, no server calls.
- Checks: the full suite ran 1595 tests, and only the known HomeScreenshotTest timeouts (3) failed;
  that class passes 5/5 on its own. ktlint required renaming the file to `QualityPreset.kt`. After
  that, ktlintCheck, lintDebug and assembleDebug pass, and SettingsScreenTest passes 15/15.
