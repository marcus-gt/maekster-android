# M2.4 Part D: Library letter rail

**Status:** complete for Library Albums, Artists and Songs (12 Nov 2026). Built by Codex; reviewed, fixed,
re-verified and committed by Claude Code (see Git).

## What was built

- Name/title sorts show a 48dp-wide, scrollable column of letter buttons beside the paged list.
- A letter jumps directly to its first absolute row position, including unloaded pages.
- Other sorts and empty lists have no rail. No server calls, dependency or schema changes.
- Existing search, favorites/download filters, offline mode, reverse order and sort-name modes apply.

## Key files and decisions

- `data/db/LetterBuckets.kt`: row_number over existing filter and name-order SQL, grouped minimum ordinal;
  returns at most 27 rows, not song/album IDs or the whole library. Positions follow existing SQLite order.
- Common accented Latin initials fold into A–Z; digits, punctuation and other scripts share #.
  Rail order follows first occurrence in the list, including descending lists.
- Leading whitespace is ignored for the bucket but existing sort order is preserved. Space-prefixed
  titles may therefore be the first match for a letter before the ordinary alphabetic section.
- `LibraryDao`, `LibraryRepository`, `LibraryViewModel`: observed local bucket flows, collected only while
  the list subscribes. Sort-name preferences feed both list and buckets.
- Artists now enables Paging placeholders and renders unloaded rows at 72dp, keeping jumps bounded.
- `LetterRail.kt`, `AlbumsContent`, `ArtistsContent`, `LibrarySongsContent`, `LibraryScreen`: jump UI.
- Album grid jumps align to the row containing the target, which may also contain preceding albums.
- 48dp buttons retain normal tap/accessibility targets; scroll the rail to reach letters below the viewport.
- Review fix: on Songs the shuffle button covered a rail letter. `LetterIndexedContent(railBottomPadding)` now
  pads the rail's scroll content (Songs passes the list's bottom inset plus the FAB clearance), so the last
  letters scroll above it. Style tidy: imports instead of inline fully qualified names; no behaviour change.

## Limits / remaining work

- Not measured at 50k albums or 200k songs; queries scan/rank in SQLite but return only buckets.
- A far jump shows blank placeholder rows for about 2–3 s on the emulator until that page loads.
- API 35, real offline downloads, TalkBack and drag-to-scrub interactions were not tested.
- Folding uses an explicit common-Latin table, not full Unicode transliteration.
- Favorites/Home lists do not gain the rail in this subtask; their existing newest-first sorts remain.
- Next M2.4 work: album metadata chips/format badge, then artist release sections and playlist footer.
  Do not start these without direction.
