## Behaviour (iOS #14 in AddToPlaylistViewModel/AddToPlaylistSheet, adapted)

- Each destination row shows how much of the selection the playlist holds: an empty circle (none),
  a partly filled one (some), or a check (all). The row's state description says it in words for
  TalkBack ("Not in this playlist", "Some songs already in this playlist", "Already in this playlist" /
  "All songs already in this playlist").
- Decided with the user: membership is read from the local mirror (`playlist_songs`), not from the
  server per visible row as iOS does. It's instant and works offline, but can lag edits made elsewhere
  until the next sync.
- Tap on a playlist holding every selected song: removes every occurrence. One song is removed
  directly; several open a confirmation ("N songs will be taken out of X." Remove/Cancel).
- Tap on any other playlist: adds only the songs it lacks (Duplicates.Skip). The old
  "Add anyway / Skip duplicates" prompt is removed, as on iOS, so the checkbox never adds a duplicate.
- Server check before every write: additions already re-read the playlist; removals compute positions
  from a fresh `getPlaylist`, never from the mirror. A stale tick therefore removes nothing and just
  refreshes the mirror (and its mark).
- Android difference: the sheet still closes after a successful add/remove with a snackbar
  ("Removed from X" / "N songs removed from X"), because the snackbar would be hidden behind an open
  sheet. iOS keeps the sheet open until Done.

## Implementation

- `PlaylistDestinationDao.held(sourceId, songIds)` (COUNT DISTINCT per playlist) and
  `PlaylistRepository.membership(...)` (Flow<Map<id, count>>).
- `PlaylistRepository.removeSongs(sourceId, playlistId, songIds)`: fresh read, then highest-first
  removal via the writer, readback mirror, Recent recorded, and the count returned. A retry re-reads,
  so it is idempotent.
- `AddToPlaylistViewModel`: `PlaylistMembership` None/Some/All in the UI, `toggle`, `confirmRemoval`,
  `dismissRemoval`, `pendingRemoval`, `songCount`. `addTo` is private and uses Skip; the duplicate
  prompt state and methods are gone. Removal clears the retained addition for that playlist.
- `AddToPlaylistSheet`: the `MembershipMark` icon replaces the playlist-add icon, and the removal
  AlertDialog replaces the duplicate dialog. The debug IME preview was updated.
- Strings: the four duplicate strings were replaced by membership/removal strings, plus
  `playlist_songs_removed`.
