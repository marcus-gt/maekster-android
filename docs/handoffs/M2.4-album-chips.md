# M2.4 Part E: album page chips and format badge

**Status:** complete (12 Nov 2026). Implemented and verified by Claude Code; committed on its own (see Git).

## What was built

- Under the album artist, a summary line: "2026 · 12 songs · 1 hr 9 min", followed by one format badge per
  distinct file suffix (at most two). Lossless formats (FLAC, ALAC, WAV, AIFF, APE, WV, DSF, DFF, TTA, SHN) use the
  lossless colour token; others are neutral. The year moved from the artist line into this summary, as on iOS.
- Below it, centred wrapping chips: up to three genres and the first record label (building icon). A chip opens
  the existing Part C collection (`collection/{kind}/{name}`) for that genre or label.
- No schema, dependency or server change. Everything comes from the Room mirror.

## Key files and decisions

- `LibraryDao.albumGenres`: the album's song tags, grouped `COLLATE NOCASE` like the Genres list, blank tags
  skipped, most-tagged first and then by name, `LIMIT 3`. The stored name is passed to navigation, so each chip
  matches its collection query. Offline (`downloadedOnly`) counts only completed downloads, so offline every
  chip's collection still contains this album.
- Label: the first non-blank `album_labels` row by position (the existing `albumLabels` query).
- `LibraryRepository.albumFacets`, `AlbumFacets` (in `data/model/AlbumCollection.kt`), `AlbumDetailViewModel.facets`.
- `ui/components/FormatBadge.kt` (`AudioFormats.isLossless` and `badges`, ready for the M2.7 player format line)
  and `ui/components/MetadataChip.kt` (a 32dp capsule inside a 48dp touch target via `minimumInteractiveComponentSize`).
- `HeroHeader` gained an optional `details` slot; only the album page uses it. Playlist and artist headers are unchanged.
- `totalDurationText` (`ui/library/TotalDuration.kt`) is now shared by the album summary and the playlist summary
  (moved out of `PlaylistDetailScreen`; no behaviour change).
- Difference from iOS: iOS makes chips non-tappable offline. Here collections work offline (downloaded albums
  only), so chips stay tappable. iOS falls back to the album's single `genre` string when there are no song genres;
  Android doesn't, because that name might match no collection.
- The summary counts the songs shown, so offline it gives the downloaded songs and their length (as iOS does).

- Final: ktlintFormat, assembleDebug, testDebugUnitTest (1,197 tests, 0 failures), ktlintCheck, lintDebug.
  The IDE shell timed out during the full run; a rerun reported every task up to date and BUILD SUCCESSFUL.

## Not verified / limits

- Offline with real downloads, API 35, TalkBack reading order, 2× font on the emulator. The UI tests run at
  normal font only, and no Roborazzi render was reviewed.
- An album whose songs have more than three genres shows only the three most tagged.
- Genre display trims whitespace, but the navigation name keeps the stored value.
