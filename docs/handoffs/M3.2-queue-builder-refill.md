# M3.2 Part E3: Queue Builder queues refill from their own picks

**Status: DONE.** Based on eb481f60 (E2b); tree clean at the start.

## Behaviour

- A queue whose stored source label is `QueueCollection.QueueBuilder` refills from the server's Queue Builder
  picks when 15 or fewer songs remain: up to 50 songs, through the same `AutoplayRefill` threshold, window
  filtering and `appendExtension` commit as autoplay.
- It refills whatever the Autoplay similar switch says. When the picks run out (nothing new matches), similar
  songs take over only if autoplay is on; otherwise the queue simply ends.
- Switching autoplay off, or restoring with it off, no longer trims the refilled tail of a Queue Builder queue.
  Repeat or shuffle still trims it, as for autoplay.
- Refills skip the nearby window (from 50 back to the end) and the last 50 plays. They use the picks as the
  picker shows them (`index.available`), and are downloads-only offline.
- The label stays "Queue Builder" (an endless source).

## Differences from iOS

- iOS turns the autoplay setting on for good when you build a queue. Android leaves your setting alone and
  ties the refill to the queue instead.
- iOS keeps the refill in memory, so a relaunch falls back to similar songs. Android keys it on the persisted
  source label, so it survives a restart.
- It uses the server's current saved picks, so editing picks while a built queue plays changes later refills.

## Implementation

- `AutoplayRefill.extend(..., ownPicks: OwnPicks?)`. With `ownPicks`, it runs even when autoplay is disabled,
  tries the picks first, and falls back to `generate` only when enabled. The candidate filter is shared.
- `PlaybackController`:
  - `builtQueueRefill` constructor parameter.
  - `builtQueue` set from the source label in `readSnapshot()` and `restore()`.
  - `refillActive = autoplayEnabled || builtQueue`, which replaces `autoplayEnabled` in scheduling, the
    network and offline cancels, disable-truncation, the restore truncation and the commit recheck.
- Koin: `builtQueueRefill` reads `queueBuilderPicks(sourceId)`, applies `builder.index(...).available(...)`,
  then `builder.build(..., excluding)`.
- No schema or dependency changes.
