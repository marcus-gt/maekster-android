# M3.5 C2: guarded AudioMuse score fetching

**Status: DONE (coordinator only; unwired).** Clean start at 3e32796f.

## Implemented

- AudioMuseScoreFetcher is an explicit-action coordinator; no UI/Koin invocation yet, no automatic traffic.
- At most 500 input IDs, deduplicated; serialized batches reuse persisted successes and session misses.
  Each batch runs chunks of at most five concurrent requests. No whole-library loads or detached scope.
- Only missing IDs fetch; offline returns cached scores and explicit unavailable IDs. Wrong source,
  unconfigured AudioMuse and unreadable tokens create no client. Client receives only AudioMuse credentials.
- StateFlow access (active source + effective offline/connectivity) and Room config observation cancel the
  structured request on source/offline/config changes. Guards recheck before requests, commits and return;
  C1's transaction guard still rejects changed configuration. All children/watchers end with the caller.
- Result separates scored, notAnalysed (404 only), unavailable and failed IDs. Transient/503/transport
  failures are retryable and never cached as absence; partial successes persist. No exception details logged.
- Session-only source/config-scoped 404 cache bounded to 2000; a new fetcher or changed configuration key gets fresh misses.
  A persistent success supersedes an earlier 404, so result categories do not overlap.
- Cache gained a config-observation flow; no schema, dependency, playback or UI changes.
