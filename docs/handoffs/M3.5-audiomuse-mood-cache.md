# M3.5 C1: persistent mood scores and Queue Builder ranking

**Status: DONE (cache/ranking foundation; unwired).** Base 8fecca0d; prior roadmap/reference edits preserved.

## Implemented

- Schema 62 adds audiomuse_mood_scores keyed by source/song, cascading from audiomuse_config.
  Disconnect or source deletion removes scores. Handwritten migration and generated exported schema.
- AudioMuseMoodCache has no network dependency. Reads at most 500 requested IDs; no whole-table loads.
- Versioned strict JSON retains named scores and ranked styles; corrupt/unknown payloads are cache
  misses. Invalid/nonfinite/out-of-range scores cannot be stored. Codec work runs on Default.
- Configuration key fingerprints URL and encrypted token, never plaintext. Changed URL/token hides old
  scores; transactional read/write guards reject a stale configuration snapshot. Conservative invalidation:
  resealing the same token with a new nonce also makes old entries miss. No TTL for successful analysis,
  following iOS; no permanent negative cache. Obsolete entries are overwritten per song.
- QueueBuilderMood includes all six moods (including Party); Song Path's five endpoint moods unchanged.
- rankMoodCandidates ranks a bounded batch by mean selected scores, excludes songs missing ANY selected
  score, retains input order for ties and limits output. No moods preserves original order.
- Read-only iOS AudioMuseMoodScorer.swift / QueueBuilderMood.swift inspected; no source copied.
- No Koin/UI/fetch wiring yet; D still includes mood radios AND Queue Builder mood picks.
