# M2.9: playlist drag reorder

**Status:** COMPLETE for bounded visible-row drag reorder; committed with this handoff.
Based on cf924e0a.

## Implementation

- Editable playlist rows have 48dp drag handles. Dragged row follows the pointer; destination row
  gets an accent highlight. One move is sent on release, none for unchanged/outside/cancelled drops.
- PlaylistDragState retains geometry only for composed lazy rows; DisposableEffect forgets each
  row on disposal and cancels if the source disappears. No whole-playlist UI materialization.
- Drops use raw PlaylistSongItem.position (duplicates/unresolved entries safe), not Paging index.
  ViewModel.moveToPosition applies the existing ownership/source/offline/busy guards; adjacent menu
  actions delegate to it. Existing move retry/abandonment flow is reused.
- Handles disappear while busy/error/read-only. Song row tap/menu/favorite/duration stay available.
- No auto-scroll: scroll to the destination first, as with Queue. This is a bounded visible-row
  interaction, without optimistic reordering of the Paging list; Room readback updates the order.
- No dependency, schema, sync or playback changes.
