# M2.7 Part H: Network-regain playback recovery

**Status:** complete (12 Nov 2026), based on clean 3ab55317.

## Implemented
- Koin injects the existing networkAvailable flow into PlaybackController.
- A typed network playback error while play is requested arms one retry for the same source,
  queue position, song and saved media time. Local files/offline mode and server refusals do not arm it.
- Available-route notifications consume that retry and reload the existing bounded window.
  No retry timer or loop; another error needs another availability notification.
- Pause, seek, stop, new window loads and offline mode cancel pending recovery.
  Active-source and queue-position/song checks reject stale retries after switching/skipping.
- Play intent is rechecked after asynchronous window resolution, so intervening pause/source changes
  can cancel autoplay. External pause events also cancel pending recovery.
- Errors still use existing UiMessage reporting.
- No schema, dependency or UI change.
