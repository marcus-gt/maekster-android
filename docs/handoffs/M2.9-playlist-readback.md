# M2.9: bounded playlist readback

**Status:** DONE (recovered and verified after an interrupted session; committed).
Based on 361c13d7.

## Implementation

- PlaylistWriter.playlistBatches(id) is a cold Flow<PlaylistBatch> for the future queue saver.
  Each batch holds the same playlist summary and at most 100 PlaylistSong entries with absolute
  Long positions. No whole destination list is materialised by the Subsonic implementation.
- SubsonicPlaylistWriter uses the existing SAX parser, a 100-entry pending buffer, rendezvous
  channel and IO dispatcher. The parser waits for handoff before advancing into the next batch.
  In-flight memory is bounded (one handed-off batch plus the parser's pending batch).
- Duplicate occurrences/order/source/playlist identity are preserved. Empty playlist emits one
  empty batch; exact multiples have no empty tail. Missing (70/404 or absent element) emits none.
- Wrong/multiple playlist identities or empty entry IDs fail instead of silently changing order.
  An error after a batch, including not-found, still fails: successful flow completion is required.
- Consumers must stage until successful completion, rather than publishing partial mirror state
  or treating the first batch as a successful read. Do not collect the whole flow into a list.
- Cancellation is checked at entry/batch boundaries and unwinds/ closes the HTTP response. A socket
  blocked before another parsed element remains subject to existing network timeouts.
- FakePlaylistWriter implements the new interface for existing tests; only its in-memory fixture
  uses the old detail helper. Existing writer/repository operations are unchanged.
- No UI, schema, dependency, server writes or production consumer added.
