# M2.8 Part F: LRCLIB provider

**Status:** COMPLETE. Based on 292e5d82; committed with this handoff.

## Implementation

- Dedicated OkHttp client, no shared server interceptors/auth/cookies, redirects and automatic
  connection retries disabled. Public constructor uses HTTPS lrclib.net/api/get only.
- Query contains trimmed title/artist, optional nonblank album and valid 1–3600s duration.
  No server IDs/credentials. User-Agent from brand constant plus project URL; Accept JSON.
- Cancellable async call; response closes on every path. Decode on Default dispatcher. 20s timeout.
- One request at a time, 250ms spacing. HTTP 429 and 503 with Retry-After set a cooldown plus
  0–30% jitter; premature subsequent requests fail locally. Invalid/missing 429 delay defaults to
  60s. No automatic busy retry yet. Singleton lifetime must preserve pacing across songs.
- 404 returns no lyrics. Other HTTP/content-type/JSON errors surface typed/generic IOException.
- LRC/plain variants or typed instrumental marker. Backward-compatible optional instrumental
  field in version-1 cache JSON; no Room migration or dependency change.
- Key files: LrclibProvider.kt, Lyrics.kt/LyricsCodec.kt and provider/cache tests.
