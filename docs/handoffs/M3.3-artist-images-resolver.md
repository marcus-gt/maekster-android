## Implemented

- `MusicBrainz.wikidataId(artistId)`: `artist/<mbid>?inc=url-rels`, first `wikidata` relation whose URL is a
  `wikidata.org/wiki/Q…` item; non-UUID ids make no request; 404 is a definite miss; shares the 1 req/s limiter.
- `data/artistimages/Wikidata.kt`: `Wikidata` interface and `OkHttpWikidata` (own client, no redirects, app
  User-Agent with homepage per Wikimedia policy). Uses `wbgetclaims` for P18 only (iOS fetches all claims).
  Preferred rank first, deprecated skipped, non-string or control-character values ignored; `no-such-entity` is a
  miss; HTTP/API/JSON errors throw.
- `data/artistimages/ExternalArtistImages.kt`: id path when the candidate has a valid MBID, otherwise the existing
  certain-only name match (`artistId`: score ≥ 90 and same normalised name; iOS also accepts any score ≥ 90).
  Commons URL built as one encoded path segment, spaces as underscores, width 500.
  Bounded LRU (500) of definite answers including misses; failures are not cached (iOS caches them as misses).
  Concurrent requests share one lookup; a cancelled waiter does not stop it; the last waiter leaving cancels it.
  The shared lookup completes with null instead of failing, so it never cancels its scope.
