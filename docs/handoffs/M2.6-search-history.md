# M2.6 Part C: Recent searches per server

**Status:** complete (12 Nov 2026). Recovered the implemented, uncommitted subtask at ac6fb330;
finished verification and added large-font coverage. M2.6's planned parts are done; see the follow-up below.

## Implemented
- As on iOS, Search remembers what you **open** from it, not the text you typed: an album, artist or playlist
  opened from the top result, a group or the history itself. Songs play rather than open, so they are not recorded.
- With an empty field, Search shows **Recent** (newest first) with a **Clear** action behind a confirmation dialog
  ("Clear search history?"). Each row shows the cover (round for artists), name and "Album · Artist", "Artist" or
  "Playlist". Tapping opens the item and moves it to the top. With no history, the existing prompt shows.
- Room schema 44 adds `search_history` (sourceId, kind, refId, visitedAt; FK cascade on server delete; index on
  sourceId + visitedAt), decision D6. Each server keeps its 50 newest items. A visit is always stamped after the
  server's newest entry, so a reopened item tops the list even within one millisecond or after the clock moves back.
- Names and covers resolve from the local mirror at read time (like pins), so renamed items stay current; items no
  longer mirrored are hidden but kept, and reappear if mirrored again. iOS stores the display name instead.
- iOS keys entries by server and item id only; Android keys by server, kind and id, so an album and an artist
  sharing an id stay separate.
- `resolveMenuTarget` (ui/components/LibraryTargets.kt) is now shared by Home pins and Search history.

## Follow-up found (not in this slice)
- iOS hides history items that are unavailable offline. Android Search currently searches the whole mirror even in
  offline mode (results and now history), so history follows that for consistency. Recommended next slice:
  offline Search shows downloaded content only (results and history), matching iOS and the rest of offline mode.
