# M3.2 Part D2: queue extension operations

**Status: DONE (repository only).** Based on 000dc9dd; initially clean.

## Implementation

- QueueRepository.appendExtension(snapshot, sourceId, songIds): at most 50 known mirrored songs,
  one Song reference each, appended with the initial extensionStart retained across refills.
  Rejects empty contexts/batches, stale context snapshots, wrong sources, repeat and shuffle.
  Unknown song anywhere rejects the whole batch before writes; oversized batches throw.
- Insert plus boundary update uses one immediate transaction under the cursor mutex.
  Queue version and stored references are checked before committing a built batch.
- truncateExtension(snapshot): deletes the unplayed suffix in one transaction and clears the marker.
  Preserves current/history references, cursor/time and the manual up-next block; when the manual block
  is current, retains the context through its anchor. Rejects stale context/anchor or shuffle.
  Uses reference lengths, never resolves album songs or materializes the song queue.
- QueueDao.deleteContextFrom performs the range deletion.
- Manual context reorder/removal/Clear upcoming clears ownership (including shuffled rewrites):
  retained generated tracks become ordinary context. Up-next edits leave ownership intact.
  Queue replacement and Undo restoration already clear the marker via replace, so restored songs
  become ordinary context too. This favors preserving user-edited tracks over deleting by stale coordinates.
- No schema/dependency change. No production caller generates/appends autoplay tracks yet.
