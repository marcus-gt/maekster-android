# M2.9: Save queue as playlist (dialog and menu)

**Status:** DONE; JVM-tested and verified on API 37 with user-authorized server writes (see below).
Based on fa57f0f2.

## Implementation

- Queue screen options menu: "Save queue as playlist…" shown when not in offline mode and the
  queue has rows (`QueueScreen.canSaveAsPlaylist` / `onSaveAsPlaylist`). The menu button now also
  appears when that is the only action. iOS puts the action in the full player menu; on Android it
  sits with the other queue actions.
- `SaveQueueRoute` / `SaveQueueDialog` (ui/playlist): name field, Save → Retry, Cancel. Each opening
  has its own ViewModel store (`PlaylistSheetScope`, keyed by an opening counter in `QueueRoute`).
  It can't be dismissed while busy, like rename.
- `SaveQueueViewModel` (Koin, cleanup on the app `io` scope): the first Save takes a snapshot, refuses
  an empty or mixed-server queue (`save_queue_empty`, `save_queue_several_servers`), and stages it via
  `PlaylistRepository.stageSave(… QueueRepository.playlistBatches …)`. An export failure maps to
  `save_queue_capture_failed`, and cancellation is still rethrown (it is an ISE). Then `saveDraft`.
- After a failure the capture is retained: the name locks, the button reads Retry, and a note explains
  the capture is kept. Retry saves the captured queue even if playback or the queue changed. `Changed`
  (new playlist edited elsewhere) discards the capture, shows `save_queue_changed` and unlocks the name
  for a new save. Other failures use `playlistEditMessage`. Closing the dialog (`onCleared`) discards
  the draft; a partly created playlist stays on the server.
- Success: snackbar "Saved the queue as %1$s" via `showMessage`, dialog closes, mirror and Recent
  are updated by the repository. New English strings only (no other locales exist).

## Device results (API 37 emulator, debug build of 73821705, user-authorized 13 Nov 2026)

- Queue: 7LLVSION album, 12 songs. Queue options showed Clear upcoming + Save queue as playlist…;
  the dialog opened focused, Save disabled until a name was typed.
- `svc wifi/data disable` (no default network), Save: field locked, error "Can't reach the server…",
  button Retry. Logcat: one `createPlaylist` attempted and failed to connect; nothing on the server.
- Network restored, Retry: busy state with the retained-capture note, then dialog closed and snackbar
  "Saved the queue as maekster save queue test". Logcat: exactly one `createPlaylist`, one
  `updatePlaylist` (12 songIdToAdd), one readback `getPlaylist`, plus cover art. No crash.
- Without sync: Home "Your playlists" shows it first; detail "marcus · Updated Today", queue order
  Illusion … Sireneh, "12 songs · 41 min"; add-to-playlist Recent lists it first ("12 songs");
  that sheet was dismissed without a write.
- Only write: new playlist `maekster save queue test` (12 songs). The user can delete it on the
  server, or via Delete playlist in the app.
- Not covered on device: lost response mid-append, process death with a retained draft, queue
  change between failure and Retry (JVM-tested), large font, landscape, TalkBack.
