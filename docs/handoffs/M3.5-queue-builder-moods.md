# M3.5 D2: Queue Builder moods

**Status: DONE.** Clean start at 3587b4f7. D (mood radios + Queue Builder moods) is now complete.

## Implemented

- `QueueBuilderSelection.moods` (C1 `QueueBuilderMood`: happy, sad, relaxed, aggressive, party, danceable),
  saved per server in DataStore (`queue_builder_moods_<sourceId>`, wire names). Moods rank, they never
  change the genre/decade match or its count (iOS semantics).
- `QueueBuilderIndex.available(selection, moodsAvailable)`: moods reach the shown/built selection only while
  AudioMuse is configured and readable for that server; they stay saved and return with AudioMuse.
- `data/mix/QueueBuilderMoodBuilder.kt`: with moods, a random pool of genre/decade matches
  (`min(max(count×4, 120), 400)`, iOS) → C2 `AudioMuseScoreFetcher` (cached scores reused; offline cached only;
  unconfigured/unreadable → unavailable) → C1 `rankMoodCandidates` (mean of picked moods; any missing score
  excludes) → best `count`, shuffled. `MoodShortfall`: SCORES_UNAVAILABLE (nothing ranked, scores missing),
  NO_MOOD_MATCH (scored but not for the picked moods), PARTIAL (shorter because some were unscored). Moods are
  never dropped silently (iOS does, with a toast). `QueueBuilder.MAX_COUNT` raised 200 → 400 for the pool.
- `QueueBuilderMoodBuilder.Refill`: the controller's built-queue refill now reads the saved picks incl. moods
  and builds exactly like Build, so refills stay consistent (offline: cached scores + downloads).
- `QueueBuilderPlayer.play` returns `QueueBuilderOutcome(started, moodShortfall)`; `queueBuilderMessage` maps
  it to snackbar text. VM: `moodsAvailable` per active source, `toggleMood`, `clearMoods`; reset clears moods.
- UI: mood chip row on the Discover card and a Moods section (FlowRow, clear, hint; offline hint) in the
  page, both only with AudioMuse; moods join the card summary ("Jazz · Happy and Party"). Neutral chips,
  consistent with "colour means genre".
- Koin: singletons `AudioMuseMoodCache`, `AudioMuseScoreFetcher` (shared `audioMuseAccess` gate),
  `QueueBuilderMoodBuilder`; ViewModel gets `AudioMuseConfiguration.observe(id).available`. PRIVACY.md updated.

## Decisions / differences

- Refill may fetch scores online: it continues a queue the user started with moods (not browse-time).
- No AudioMuse genre fallback for untagged songs (iOS `fillUntaggedGenres`): not in roadmap scope; not done.
- First mood build on a cold cache can make up to 400 score requests (5 concurrent); later builds reuse them.
